# ontrack-pair-relay

Blind relay + pairing page for `ontrack login` in headless environments
(VPS / SSH / CI). The CLI prints a pairing URL; the user completes the real
Monash SSO in their own browser; a per-session bookmarklet encrypts the session
token to the CLI's ephemeral public key and drops it in a one-shot relay
mailbox. The relay only ever sees a mailbox hash and ciphertext.

Built with TanStack Start (React) on Cloudflare Workers. The full protocol
design lives in the sibling repository:
`ontrack-cli/docs/PAIRING_RELAY_LOGIN_PLAN.md`. The CLI-side crypto reference
implementation is `ontrack-cli/src/lib/pair-login.ts` — the browser-side code
in `src/lib/pair-crypto.ts` and `src/lib/bookmarklet.ts` must stay
byte-compatible with it.

## What's here

- `src/routes/m/$id.ts` — mailbox API (TanStack Start server route, KV
  `MAILBOXES` binding):
  - `PUT /m/<64-hex>`: stores the envelope once (409 if the mailbox is taken),
    bodies over 8KB rejected (413), KV `expirationTtl` 300s.
  - `GET /m/<64-hex>`: returns the envelope and deletes it (one-shot), 404 if empty.
  - `OPTIONS`: 204 CORS preflight; every other method: 405.
  - CORS `Access-Control-Allow-Origin: *` on all mailbox responses.
  - Best-effort per-IP write throttle: 60 PUTs per 60s window, then 429
    (fails open). No request body is ever logged.
- `src/routes/index.tsx` — pairing page (React, SSR):
  - Reads `#c=<code>&k=<base64url(spki)>` from the URL fragment (never sent
    over the network) and generates the session bookmarklet.
  - Three-step flow: drag bookmarklet to the bookmarks bar (first time) →
    open OnTrack sign-in → click the bookmark on the OnTrack page.
  - Fallbacks: copyable bookmarklet, a paste-the-landing-URL form (mobile),
    and a `#d=` receiver for when OnTrack's CSP blocks the bookmarklet's fetch
    (the bookmarklet navigates to `#d=<envelope>&m=<mailboxId>` and this page
    delivers it).
  - English/Chinese i18n (`src/lib/i18n.ts`), auto-detected from
    `navigator.language` with a manual toggle; the bookmarklet's alert strings
    are baked in the active language.
- `src/lib/pair-crypto.ts` — ECIES matching the CLI exactly: ECDH P-256 →
  HKDF-SHA256 (salt = 32 zero bytes, info `ontrack-pair-v1`) → AES-256-GCM,
  12-byte nonce, envelope `{"v":1,"eph","nonce","ct"}` base64url without
  padding; mailboxId = SHA-256 hex of the pairing code.
- `src/lib/bookmarklet.ts` — bookmarklet source template and builder.
- `scripts/smoke.mjs` — smoke test against a running deployment.

## Develop

Requires [bun](https://bun.sh) (the only package manager used here — never
npm/npx).

```sh
bun install
bun run dev        # vite dev on http://localhost:5173 (local KV simulation)
bun run smoke      # smoke test: BASE_URL=http://localhost:5173 bun run smoke
```

The smoke test covers: PUT → GET → GET 404 (one-shot delivery), duplicate PUT
409 without overwrite, invalid id 400, oversized body 413.

Other scripts:

```sh
bun run build      # vite build -> dist/ (client + server)
bun run cf-typegen # regenerate worker-configuration.d.ts from wrangler.jsonc
bunx tsc --noEmit  # type-check
```

`src/routeTree.gen.ts` and `worker-configuration.d.ts` are generated artifacts
(gitignored); they are regenerated by the build and `cf-typegen`.

## Deploy

```sh
bun run deploy     # vite build && wrangler deploy
```

`wrangler.jsonc` pins the KV namespace id and the `pair.markchu.work` custom
domain. To recreate the namespace from scratch:

```sh
bunx wrangler login
bunx wrangler kv:namespace create MAILBOXES
# paste the printed id into wrangler.jsonc
```

**After deploying**, update the CLI so `ontrack login` prints the real URL:
set `DEFAULT_RELAY_URL` in `ontrack-cli/src/lib/pair-login.ts` to the deployed
origin. For ad-hoc testing you can instead use `ONTRACK_RELAY_URL` or
`ontrack login --relay-url <url>`.

```sh
BASE_URL=https://pair.markchu.work bun run smoke   # against production
```

## Notes

- The pairing page derives everything from the URL fragment and its own
  origin — there is no per-deploy configuration baked into the page.
- Pairing codes are single-use and the mailbox expires after 5 minutes; an
  expired or consumed mailbox just makes the CLI keep waiting until timeout,
  after which it falls back to manual URL capture.
